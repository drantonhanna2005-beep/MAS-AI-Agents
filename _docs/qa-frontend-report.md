## 2. نتائج المهام الأربع

### 2.1 مشغل الفيديو (المهمة الأساسية)

| الاختبار | النتيجة |
|---|---|
| تحميل المقطعين | ✅ `readyState = 4` للملفين، `duration = 4s` |
| تشغيل فعلي | ✅ `data-playing="1"` في Chrome headless (سياسة autoplay مسموحة) |
| تبديل idle ↔ talk | ✅ يتغيّر `currentSrc` إلى `talk.mp4` عند أول محتوى ويعود عند `idle` |
| شريط التقدم | ✅ يعرض الوقت الحالي، النقر/السحب يغيّر `currentTime`، ويحترم اتجاه RTL |
| إعادة من البداية | ✅ ترجع إلى 0 وتكمل التشغيل |
| كتم/فتح الصوت | ✅ يطبَّق على المقطع النشط فقط |
| ملء الشاشة | ⚠️ الكود يستخدم Fullscreen API على `.av-screen` — لم يُختبر بصريًا في البيئة الحالية |
| عدم وجود أصول | ✅ يتحوّل تلقائيًا إلى avatar SVG متحرك بدل شاشة سوداء |
| تبويب مخفي | ✅ الفيديو يتوقف، ويعود عند إظهار التبويب (سياسة المتصفح) |

### 2.2 دورة الحالة أثناء الرد

تم تسجيل أحداث `avatarstate` أثناء إرسال سؤال حقيقي إلى الخادم:

```
thinking → thinking (route) → speaking → idle
```

| الاختبار | النتيجة |
|---|---|
| فتح تلقائي عند بدء الرد | ✅ `data-open="true"` |
| طي تلقائي بعد الانتهاء | ✅ بعد 4.2 ثانية يعود `data-open="false"` ويظهر الـ orb |
| التثبيت (pin) | ✅ يمنع الطي ويُحفظ في `localStorage` |
| اسم الوكيل في الرأس | ✅ يتحدّث من حدث `route` (مثال: «المرشد الأكاديمي — يراجع اللائحة») |
| حالة الخطأ | ✅ مسار الكود يضبط `error` ويعرض «تعذّر التشغيل» (لم يُحاكَ خطأ SSE حقيقي) |

### 2.3 توحيد الهوية البصرية

| البند | قبل | بعد | التحقق |
|---|---|---|---|
| أحجام الخطوط | 22 قيمة | 12 token | `rg "font-size"` → صفر قيم px خام |
| ألوان النجاح | 3 hex خارج اللوحة | `var(--ok)` | فحص `style.css` |
| z-index | أرقام حرة | 5 tokens | `--z-avatar` = 45 مطبّق فعليًا |
| سطح لوحة الـ avatar | شفاف + blur | صلب `var(--card)` | التباين مقروء في الثيمين |
| حركة الدخول | `opacity` من 0 | `transform` فقط | لا شفافية عالقة عند تجمّد الحركة |
| الخط | Cairo | Cairo | ثابت في الثيمين والاتجاهين |

التفاصيل الكاملة في [`design-system.md`](design-system.md).

### 2.4 التجاوب

| العرض | النتيجة |
|---|---|
| 1440 / 1280 | البطاقة 268px أسفل الجهة المقابلة للشريط — لا تعارض مع الشريط الجانبي |
| 768 | البطاقة 232px، لا تغطية للـ composer |
| 390 / 360 | فقاعة 122px أثناء الرد، تتوسّع إلى 206px باللمس |
| ارتفاع < 620px | تُصغَّر البطاقة إلى 176px ويُخفى السطر الثاني من الرأس |
| ارتفاع < 460px | 148px مع إخفاء شريحة الحالة والوقت |
| RTL | زر الإغلاق/التصغير في مكانه المنطقي، والمشغل يبقى LTR |
| LTR | إزاحة 50px عن اليمين لتجنّب شريط التنقل بين الرسائل |

## 3. العيوب التي ظهرت وأُصلحت

| # | العيب | الإصلاح |
|---|---|---|
| 1 | ملامح الوجه والشعر لا تُرسم في مقاطع الـ avatar | إعادة إنشاء فرشاة الرسم بعد كل `alpha_composite` في `avatar_gen.py` |
| 2 | الرقبة رقيقة والسماعة عائمة خارج الرأس | إعادة ضبط هندسة الرأس/الرقبة/شريط السماعة (1024px) |
| 3 | أدوات المشغل تنعكس في RTL (تشغيل يمين، ملء الشاشة يسار) | `direction: ltr` على `.av-bar` فقط |
| 4 | زر التكبير يظهر على الديسكتوب | رفع التخصيص إلى `#avatarStage .av-zoom` |
| 5 | البطاقة تغطي نص الرد على الموبايل | نمط mini 122px + توسيع باللمس |
| 6 | البطاقة تتقاطع مع شريط التنقل في LTR | إزاحة `inset-inline-end: 50px` |
| 7 | ألوان/أحجام خطوط غير موحّدة | tokens + إزالة القيم الشاذة (41 استبدالًا + 86 توكنًا) |

> ملاحظة: تم التحقق من عدم وجود تداخل طبقات فعلي عبر `elementFromPoint`
> (يعيد عنصر الفيديو داخل البطاقة) بعد أن أوحت صور مصغّرة بخلاف ذلك.

## 4. ما لم يُغطَّ

1. **TTS بصوت حقيقي** — لا يوجد مفتاح مزوّد في البيئة، فمسار `bindAudio` لم يُشغَّل بصوت فعلي
   (الكود يحتوي على fallback في حال رفض المتصفح).
2. **إدخال صوتي بالميكروفون** — لا صلاحية ميكروفون في بيئة الاختبار؛ حالة `listening`
   اختُبرت برمجيًا فقط.
3. **ملء الشاشة** — يحتاج نقرة مستخدم حقيقية؛ الكود يستخدم `requestFullscreen` مع `catch`.
4. **مقاطع مخصّصة لكل وكيل** — غير مطلوبة حاليًا.

## 5. إعادة الاختبار

```bash
# 1) تشغيل الخادم
python app.py --port 8765 --no-browser

# 2) فتح الواجهة
http://127.0.0.1:8765/

# 3) تجربة الـ avatar مباشرة
http://127.0.0.1:8765/?avatar=speaking

# 4) معاينة على مقاس محدد (390 موبايل / 768 تابلت / 1440 ديسكتوب)
http://127.0.0.1:8765/static/qa/viewport-preview.html?w=390&h=760&open=1&state=speaking
```

فحص سريع من الـ Console:

```js
AvatarStage.setState("speaking");   // يجب أن يتحول للفقاعة/البطاقة ويتكلم
AvatarStage.setState("idle");       // يعود بعد 4.2 ثانية (إن لم يكن مثبتًا)
document.getElementById("avatarStage").dataset.playing; // "1" أثناء التشغيل
```
